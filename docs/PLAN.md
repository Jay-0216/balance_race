# 결정 장애 레이스 (Decision Dilemma Race) — 개발 플랜

> 지식이 아니라 **선택**으로 달리는 경주.
> 매 라운드 둘 중 하나를 고르고, **다수와 같은 선택**을 하면 전진한다.
> "남들이 뭘 고를까"를 읽는 눈치게임.

---

## 0. 결정된 전제

| 항목 | 결정 |
|---|---|
| 플레이 방식 | 온라인 실시간 멀티 + 봇 (봇은 빈자리 채우기 & 싱글 모드) |
| 우선순위 | **레이스 시각화가 1순위.** 게임 로직보다 먼저 만든다 |
| 플랫폼 | 웹 먼저 → 같은 코드로 앱(Capacitor) |
| 화면 기준 | 처음부터 **세로 9:16 + 터치 우선**. 앱 전환 때 다시 안 짜려면 필수 |

## 1. 게임 규칙

### 1.1 한 라운드 (약 20초)

```
딜레마 제시 (10초 카운트다운)
        ↓
전원 선택 (남의 선택은 안 보임)
        ↓
집계 공개 애니메이션
        ↓
이동 — 다수 전진 / 소수 제자리
        ↓
순위 갱신 → 다음 라운드
```

총 12라운드 또는 결승선(**20칸**) 선착.

### 1.2 이동 규칙 — 여기가 밸런싱의 핵심

단순히 "다수 +1, 소수 0"으로만 하면 **다수가 계속 뭉쳐서 순위가 안 갈린다.**
1등이 안 바뀌면 재미가 없다. 그래서 변동성을 넣는다.

| 상황 | 효과 |
|---|---|
| 기본 | 다수 **+2칸**, 소수 **0칸** |
| 압도 (다수 85%↑ = 7-1, 8-0) | 다수 **+1칸** — 뻔한 선택은 이득이 적다 |
| 극소수 (소수 30% 미만 = 1~2명) | 그 소수에게 **부스터** 지급 → 다음 라운드 다수면 **+6칸** |
| 동점 | **전원 +1칸, 부스터는 그대로 유지** — 아무도 못 읽은 판. 짝수 인원에서 동점은 자주 나오므로 레이스가 멈추지 않게 한다 |

> 🔬 **"박빙 +3칸" 규칙은 폐기했다.** 1000판 시뮬레이션이 두 가지를 잡아냈다.
>
> 첫째, **8명에서 나올 수 있는 분할은 5-3(62.5%) / 6-2(75%) / 7-1(87.5%) / 8-0뿐이다.**
> "51~60%" 구간은 애초에 존재할 수 없어서 +3은 한 번도 발동하지 않는 죽은 코드였다.
> 임계값은 실제로 나올 수 있는 비율 사이에 놓아야 한다.
>
> 둘째, 임계를 65%로 고쳐서 5-3에 +3을 주자 **오히려 순응형이 유리해졌다.**
> 5-3의 5쪽은 결국 군중이고, 순응형 봇이 거기 앉아 있기 때문이다.
> 무난이 우승률 18.7% → 19.5%, 선두 교체는 3.10회 → 2.46회로 줄었다.
> 좁게 이긴 쪽에 더 주는 건 **읽은 사람이 아니라 따라간 사람에게 주는 보상**이었다.
> 그래서 일반 승리는 일괄 +2로 두고, 눈치를 보상하는 무게는 전부 부스터로 옮겼다.

> ⚠️ **동점 라운드에서 부스터가 터지면 안 된다.** 동점은 "아무도 못 읽었다"는 뜻이라
> 누구도 부스터를 쓸 자격이 없다. 동점을 승리 처리에 묶으면 부스터 보유자만 +5로 튀어나가는데,
> **부스터 보유자는 정의상 직전에 극소수였던 사람 = 대개 꼴찌**라서
> 맨 뒤가 갑자기 치고 나가는 것처럼 보인다. 목업에서 실제로 났던 버그다.

**부스터가 이 게임의 심장이다.** "다들 A 고를 것 같은데... 일부러 B 가서 부스터 먹고 다음에 크게 갈까?"
= 지금 지는 걸 감수하고 다음을 노리는 도박. 눈치게임이 두 겹이 된다.

부스터 임계도 시뮬레이션으로 정했다. 25%에서는 8명 중 **혼자** 반대해야만 자격이 생겨서
게임당 1.2회밖에 안 터졌고 순응형을 전혀 견제하지 못했다. 30%로 올려 2명까지 인정하니
5.4회로 늘었다. 40%까지 열면 10.6회 — 도박이 아니라 일상이 되고 우승 분포는 오히려 나빠졌다.

### 1.3 특수 라운드 (지루함 방지)

| 라운드 | 이름 | 규칙 |
|---|---|---|
| 5 | **더블** | 이동 거리 2배 |
| 8 | **역전** | 소수가 전진, 다수 제자리 (라운드 시작 전 미리 공지 → 심리전 폭발) |
| 12 | **올인** | 자기 칸 수 중 일부를 베팅. 다수면 2배 획득, 소수면 잃음 |

미리 공지하는 게 포인트. "역전 라운드인 걸 다들 아니까, 다들 소수를 노리면 그게 다수가 된다."

## 2. 딜레마 카드

### 2.1 데이터 구조

```json
{
  "id": "school_012",
  "category": "학교생활",
  "a": { "text": "숙제 안 하고 지금 놀기", "emoji": "🎮" },
  "b": { "text": "숙제 먼저 하고 나중에 자유시간", "emoji": "📚" },
  "popularBias": 0.38
}
```

`popularBias` = 실제 사람들이 A를 고를 예상 비율. **봇 AI와 난이도의 기준값**이 된다.

### 2.2 카테고리

학교생활 / 인간관계 / 먹을거 / 도덕적 딜레마 / 미래·진로 / 완전 헛소리

### 2.3 목표 수량

- MVP: **40장** (한 판 12라운드 → 3판은 안 겹침)
- 정식: 150장

> ⚠️ **카드 퀄리티가 게임 재미의 절반이다.** 시각화가 아무리 좋아도 딜레마가 시시하면 끝.
> `popularBias`는 상상으로 채우지 말고 친구들 20명한테 실제로 물어보고 채운다.

## 3. 레이스 시각화 ⭐ 최우선

### 3.1 레이어 구조

```
┌─ UI 레이어        딜레마 카드 · 타이머 · 순위표 · 집계 바
├─ 파티클 레이어    Canvas — 먼지, 스피드라인, 부스터 불꽃, 컨페티
├─ 캐릭터 레이어    DOM — 러너 8명 (클릭/디버깅 쉬움)
├─ 트랙 레이어      SVG — 곡선 path, 칸 눈금, 결승선
└─ 배경 레이어      패럴랙스 3겹 × 테마 4종
```

**하이브리드로 가는 이유:** 캐릭터를 DOM으로 두면 CSS 애니메이션·개발자도구 디버깅이 쉽고,
파티클처럼 수백 개 도는 건 Canvas가 압도적으로 빠르다. 각자 잘하는 걸 시킨다.

### 3.2 곡선 트랙

직선 트랙은 지루하다. SVG `<path>`로 구불구불한 트랙을 그리고,
`path.getPointAtLength(진행도 × 전체길이)`로 캐릭터 좌표를 계산한다.
같은 함수로 접선 각도까지 구해서 캐릭터를 트랙 방향으로 기울인다.

### 3.3 패럴랙스 배경과 테마 (구현 완료)

3겹 (먼 0.2배속 / 중간 0.5배속 / 앞쪽 1.2배속) × 테마 4종:
**새벽 학교 → 한낮 운동장 → 도시 밤 → 우주.**

테마는 라운드가 아니라 **선두의 진행도(0~1)**에 물려 있다. 네 테마를 겹쳐 쌓고
인접한 둘의 opacity를 교차시켜서 컷이 아니라 디졸브로 넘어간다.
숫자를 안 봐도 "많이 왔구나"가 보인다 — 배경이 곧 진행바다.

> **도로 색도 테마마다 같이 바뀌어야 한다.** 배경만 밝히면 도로가 땅에 묻힌다.
> 테두리·노면·중앙선 3색을 테마별로 두고 배경과 같은 가중치로 RGB 보간한다.
> 한낮에는 밝은 회색 아스팔트에 흰 중앙선, 우주에서는 보라 노면에 네온 중앙선.
>
> 이래서 배경 테마를 Phase 3이 아니라 Phase 1에서 당겨 넣었다.
> 나중에 넣으면 레이서·도로 팔레트를 처음부터 다시 잡아야 한다.

### 3.4 레이서 — 경주용 차

위에서 내려다본 F1 스타일. 뒷바퀴가 넓고 코가 뾰족하며 리어윙과 콕핏이 있다.
차체 17 × 9유닛(폰에서 약 15px)이라 디테일은 실루엣으로만 읽히는 게 정상이다.

차 모양이라 **스쿼시를 원보다 훨씬 세게 줄 수 있다.** 원을 늘이면 그냥 깨진 원이지만,
차를 제 길이 방향으로 늘이면 모션블러로 읽힌다. 최대 `scale(1.62, 0.72)` — 대시하는 순간
차가 확 늘어났다 착지한다. 잔상·스피드라인과 겹치면 튀어나가는 느낌이 확실히 산다.

### 3.5 상시 주행 — 차가 실제로 간다

레이스 결과와 무관하게 **차는 항상 달리고 있어야 한다.** 라운드 결과는 누가 앞서느냐만 정한다.

처음엔 배경만 흘리는 **트레드밀**로 만들었는데 두 군데서 틀어졌다:

1. **출발 위치에서 이상하다.** 차가 제자리에 붙어 있고 배경만 흐르니 미끄러지는 것처럼 보인다.
2. **도로가 곡선이라 더 이상하다.** 배경을 가로로만 밀면 흐르는 방향과 도로 방향이 어긋난다.

그래서 **진짜로 전진시킨다.** 도로 위의 모든 것 — 차, 칸 눈금, 출발선, 결승선 — 을
`(점수 + cruise)` 위치에 그린다. 전부 같은 오프셋을 쓰므로 **서로 간의 거리는 정확히 점수 그대로**이고,
결승선도 20칸 앞에 그대로 있어서 1위가 20칸에 닿는 순간 실제로 만난다.
카메라가 따라가면 배경 패럴랙스는 저절로 흐른다.

| 항목 | 값 |
|---|---|
| 상시 속도 | **0.25칸/초** (10초 라운드에 2.5칸) |
| 트랙 길이 | 200칸 분량 + 앞쪽 12칸 |
| 앞쪽 여유(lead-in) | 출발선 뒤로도 도로가 있어야 **둥근 끝단이 안 보인다** |

### 3.5.1 엎치락뒤치락 (jostle)

전원이 같은 속도로 붙어 가면 대형이 뻣뻣하다. 각 차에 주기가 다른 사인파 두 개를 겹쳐서
**±0.25칸 안쪽으로 미세하게 앞뒤를 주고받게** 했다. 순위를 오독할 크기는 아니고, 살아 있어 보인다.

### 3.5.2 바람과 불꽃

| 순간 | 연출 |
|---|---|
| 다수 쪽이 전진 | 차 뒤에서 **흰 바람 줄기**가 길게 뿜어져 나옴 (0.7초) |
| ↳ 바람의 좌표계 | **화면이 아니라 트랙 좌표**에 뿌린다. 각 입자가 `(칸, 좌우 오프셋)`을 들고 뒤로 밀려나며, 매 프레임 도로 위 좌표로 투영된다. 화면 좌표에서 직선으로 날리면 **곡선 구간에서 바깥으로 튀어 나간다** |
| 부스터 발동 | 차 뒤에서 **불꽃이 화르륵** — 흰→노랑→주황→빨강, 위로 솟음 (0.95초) |

> ⚠️ **파티클 풀에서 불꽃이 바람에게 밀린다.** 7대가 동시에 바람을 뿜으면 풀이 바닥나고
> `take()`가 null을 돌려주는데, 하필 같은 프레임에 터지는 **부스터 불꽃이 자리를 못 잡는다.**
> 풀을 560개로 키우고 **불꽃을 바람보다 먼저 처리**해야 한다.
>
> 그리고 이펙트는 **연출 공개(reveal)가 아니라 실제 이동(moving) 시점**에 걸어야 한다.
> reveal에 걸었더니 차가 움직이기도 전에 바람이 끝나 있었다.

### 3.6 카메라

- 선두와 꼴찌를 모두 담되 선두 쪽에 여유를 준다
- SVG `viewBox`를 매 프레임 lerp(0.08)로 부드럽게 보간
- 순위가 크게 바뀌는 순간 살짝 줌아웃 → 다시 줌인

### 3.6.1 딜레마 카드 등장

A와 B가 **양쪽 화면 밖에서 쾅 날아 들어와 가운데서 부딪힌다.** 부딪히는 순간
그 자리에서 **VS가 또잉 하고 튀어나오고**, 카드는 반동으로 좌우로 밀려나 제자리에 앉고
VS는 둘 사이 가운데에 남는다. 총 0.62초.

타이밍은 셋이 공유한다 — 카드가 만나는 지점이 38%라서 VS도 거기서 시작해
카드가 아직 튕겨 나가는 동안 1.75배까지 오버슈트했다가 가라앉는다.

라운드마다 다시 재생돼야 하므로 카드 컴포넌트를 라운드 키로 remount한다.

### 3.7 결과 공개 타임라인 (게임의 하이라이트)

| 시각 | 연출 |
|---|---|
| 0.0s | 딜레마 카드 3D flip으로 뒤집힘 |
| 0.3s | 집계 바가 좌우에서 차오름 + 숫자 카운트업 |
| 0.8s | **"다수!"** 도장 쾅 (scale 1.5→1, 화면 흔들림 6px) |
| 1.0s | 다수 캐릭터 동시 대시 — 먼지 파티클 + 스피드라인 + 잔상 |
| 1.8s | 소수 캐릭터 좌절 (제자리 점프, 땀방울) |
| 2.2s | 순위표 FLIP 애니메이션으로 재정렬 |
| 2.6s | 부스터 획득자 머리 위 불꽃 아이콘 |

캐릭터 이동은 `cubic-bezier(.22,1,.36,1)` 0.8초 — 확 튀어나갔다가 부드럽게 멈춘다(ease-out).
달릴 때 squash & stretch를 넣으면 같은 코드량으로 체감 퀄리티가 두 배가 된다.

### 3.8 타이머 이펙트

10초 카운트다운은 숫자가 아니라 **이 게임의 긴장 그 자체**다. 레이스 화면 우측 상단에 원형 링 게이지로 띄운다.

| 요소 | 내용 |
|---|---|
| 색 전이 | 시안(여유) → 앰버(주의) → 코랄(촉박). RGB 보간으로 이어지고, 마지막 3초는 `pow(t,2)` 커브로 빨강이 빨리 온다 |
| **잠금 핍** | 딜레마 카드 바로 위에 인원수만큼 핍. 누군가 선택을 확정하면 왼쪽부터 하나씩 채워진다 |
| 마지막 3초 | 링이 `scale 1 → 1.11`로 심장박동, 화면 가장자리 붉은 비네트가 같은 박자로 숨 쉼. 앱에서는 햅틱 추가 |
| 내가 선택 | 링이 골드로 잠김 |
| 시간 초과 | 링이 부풀며 흩어지고 자동 랜덤 선택 |

> **잠금 핍이 핵심이다.** 몇 명이 이미 골랐는지는 보이지만 **뭘 골랐는지는 안 보인다.**
> 정보는 한 톨도 안 흘리면서 압박만 정확히 전달한다.
>
> 처음엔 링 둘레에 점으로 돌렸는데 **영락없는 타이어로 보였다.** 원형 게이지 테두리에 점을 박으면 무조건 휠이 된다.
> 링은 카운트다운만 하게 두고, 핍은 실제로 고민하는 자리인 카드 쪽에 놓는다.

구현은 `setInterval`이 아니라 `performance.now()` 기준 `requestAnimationFrame`으로 간다.
setInterval은 탭을 옮기거나 프레임이 밀리면 시간이 조금씩 어긋나는데,
온라인에서 그 오차는 **내 화면과 남의 화면의 마감 시각이 달라진다**는 뜻이라 그냥 버그다.
reduced-motion에서는 pulse와 비네트만 끄고 링은 남긴다 — 남은 시간은 연출이 아니라 정보다.

### 3.9 성능

목표 60fps. `transform`/`opacity`만 애니메이트하고 파티클은 객체 풀로 재사용한다.
Phase 3에서 실제로 프레임을 깎아먹은 것 셋:

| 원인 | 증상 | 처리 |
|---|---|---|
| 파티클마다 `save/rotate/restore` | 대시 중 60 → 41fps | 알파를 4단계로 버킷팅해 **버킷당 `stroke()` 한 번**. 이 크기에서 4단계와 연속 페이드는 구분이 안 된다 |
| 파티클마다 `getPointAtLength` 2회 | 바람 100개 × 2 = 200회/프레임 | 트랙을 **칸당 4점으로 한 번만 샘플링**해 `Float32Array`에 넣고 선형 보간. 이 완만한 도로에서 오차는 1픽셀 미만 |
| 결과 화면 `backdrop-filter` | **25fps** | 블러 뒤에서 캔버스가 60fps로 계속 다시 그려지고 있었다. 게임이 끝나면 **레이스 루프를 아예 멈춘다** |

카운트업 숫자도 `setState`가 아니라 **ref로 DOM에 직접 쓴다** — 프레임마다 상태를 바꾸면
하필 프레임 예산이 제일 빠듯한 대시 순간에 패널 전체가 60번 다시 렌더된다.

저사양에서는 파티클 수를 자동으로 줄이고, `prefers-reduced-motion`에서는
파티클·흔들림·슬램을 전부 끄되 **남은 시간과 순위는 연출이 아니라 정보이므로 유지한다.**

## 4. 봇 AI

각 봇에 성향 파라미터를 준다:

| 파라미터 | 의미 |
|---|---|
| `conformity` 0~1 | 다수를 따라가려는 정도 |
| `contrarian` 0~1 | 일부러 반대로 가는 정도 |
| `risk` 0~1 | 부스터·베팅을 노리는 정도 |
| `noise` 0~1 | 그냥 랜덤하게 튀는 정도 |

선택 확률 = `sigmoid(popularBias 보정 + 성향 가중 + 노이즈)`

캐릭터 이름에 성향을 드러낸다: **무난이**(conformity 高) / **청개구리**(contrarian 高) / **눈치백단**(conformity 高 + noise 低) / **도박러**(risk 高).
플레이어가 "쟤는 어차피 반대로 갈 거야"를 읽을 수 있게 되면 게임이 한 단계 깊어진다.

## 8. 단계별 계획

### Phase 0 — 준비 (0.5일) ✅ 완료
Vite + React + TS 세팅 / 폴더 구조 / 세로 9:16 레이아웃 셸 / GitHub Pages 배포 워크플로

`.stage`가 9:16 프레임을 강제한다. 데스크톱에서는 레터박스로 감싸고 모바일에서는 화면을 꽉 채우는데,
**두 벌을 만드는 게 아니라 같은 레이아웃 한 벌**이다. Capacitor 래핑이 재작성이 아니라 감싸기로 끝나는 이유가 이거다.

### Phase 1 — 레이스 시각화 프로토타입 ✅ 완료

`src/race/` — SVG 곡선 트랙, 8명 레이서, ease-out 이동, 스쿼시&스트레치,
잔상·먼지·스피드라인 파티클, 패럴랙스 3겹, 팩 프레이밍 카메라, 체커 결승선.
`혼자 하기` → 레이스 프로토타입. **폰·노트북 모두 60fps 유지.**

게임 로직은 일부러 하나도 없다. `랜덤 전진` 버튼이 무작위로 몇 명을 앞으로 보낼 뿐이다.
이 화면이 답해야 하는 질문은 "보는 게 재밌나" 하나뿐이라서.

#### 확정된 수치

| 항목 | 값 |
|---|---|
| 월드 | 1200 × 250 유닛, 40칸 (셀당 28유닛) |
| 레이서 | 차체 17 × 9, 레인 간격 13, 트랙 방향 지그재그 ±3.5 |
| 도로 폭 | 112 |
| 레이스 뷰 | **13:9 밴드**, `max-height: 46vh` |
| 카메라 | 팩 전체 프레이밍, 줌 상한 1.7배, 포커스 0.58 |
| 스쿼시 | 최대 `scale(1.62, 0.72)` |
| 배경 | 테마 4종 교차 페이드, 도로 팔레트 동반 보간 |

#### 만들면서 알게 된 것

1. **목업이 가로라서 그대로 못 옮긴다.** 세로 9:16 박스에 가로 트랙을 넣으면 위아래가 통째로 빈다.
   레이스 뷰를 화면에 꽉 채우지 말고 **13:9 밴드로 고정**하는 게 답이었다.
   남는 아래 공간이 딱 딜레마 카드와 순위표 자리라, 결국 실제 게임 레이아웃과 같아진다.
2. **8명 레인이 세로 공간을 다 먹는다.** 간격을 좁히면 한 덩어리로 뭉치고, 넓히면 하늘이 사라진다.
   레인 간격은 13으로 두고 **트랙 방향으로 ±3.5씩 지그재그**를 줘서 겹침을 풀었다.
   0.125칸이라 순위를 오독할 정도는 아니고, 눈으로는 확실히 갈린다.
3. **카메라로 전원을 담으려 하면 안 된다.** 막판엔 스프레드가 트랙 전체라 다 담으면 전부 점이 된다.
   줌 상한 1.7배를 두고, 넘으면 꼴찌는 화면 밖으로 보낸다 — 그러라고 순위표가 있다.
4. **줌아웃하면 월드 바닥 아래가 보인다.** 배경 언덕을 `WORLD.h`까지만 채웠더니
   그 아래로 하늘 그라디언트가 비쳐서 밝은 이음선이 생겼다. `WORLD.h + 400`까지 채워야 한다.
5. **스쿼시는 생각보다 훨씬 약하게.** 처음 `0.45`로 넣었더니 캐릭터가 타원이 됐다. `0.16`이 적당하다.
6. **애니메이션은 React 밖에서 돌린다.** 칸 위치(`pos`)만 state로 두고,
   화면 좌표·스쿼시·카메라는 ref에 직접 DOM으로 쓴다. 8명이 달려도 리렌더가 0이다.

### Phase 2 — 싱글 게임 루프 ✅ 완료

`src/game/` (순수 로직) + `src/ui/` + `src/screens/GameScreen.tsx`.
`혼자 하기` → 봇 7명과 12라운드 실제 게임. 딜레마 40장, 10초 타이머와 잠금 핍,
집계 바, 부스터, 특수 라운드 3종, 결과 화면까지.

`game/`은 렌더링을 전혀 모르기 때문에 화면 없이 그대로 시뮬레이션할 수 있다.
`npm run simulate` → 1000판 자동 대국.

#### 1000판 시뮬레이션 결과

| 지표 | 값 |
|---|---|
| 최다 우승 점유율 | 21.1% (이상적 12.5%) |
| 선두 교체 | 2.96회 / 게임 |
| 평균 라운드 수 | 10.6 |
| 결승선 도달로 종료 | 91.4% |
| 동점 라운드 | 2.46회 / 게임 |
| 부스터 발동 | 5.40회 / 게임 |

우승 분포: 나 21.1 / 무난이 20.1 / 청개구리 13.1 / 눈치백단 12.2 /
대충이 9.6 / 도박러 9.0 / 츤츤이 8.3 / 몰빵이 6.6 (%)

#### 시뮬레이션이 바꾼 것

1. **결승선 40칸은 도달 불가능이었다.** 12라운드 동안 1위가 평균 14칸까지밖에 못 갔다.
   체커 깃발이 장식이었을 뿐 아니라, **배경 테마가 선두 진행도에 물려 있어서 4번째 테마(우주)를
   실제 게임에서는 아무도 못 보는 상태**였다. 20칸으로 줄이니 91.4%가 결승선에서 끝난다.
2. **"박빙 +3"은 발동 불가 + 역효과였다** (1.2 참고).
3. **부스터 임계 25%는 게임당 1.2회.** 30%로 올려 5.4회.

#### 남은 이슈

순응형(무난이)이 여전히 20.1%로 이상치 12.5%보다 높다. 최하위 몰빵이(6.6%)와 3배 차이다.
"그냥 다수 따라가기"가 최상위권 전략인 건 눈치게임으로서 아쉽다.
다만 **선두가 게임당 3번 바뀌고 어떤 성향도 죽지 않았으므로** 치명적이진 않다고 보고 넘어간다.
Phase 3에서 특수 라운드 비중을 늘리는 쪽으로 다시 볼 것.

### Phase 3 — 연출 다듬기 ✅ 완료

| 항목 | 내용 |
|---|---|
| 상시 주행 | 트레드밀 폐기, 실제 전진 (3.5) |
| 엎치락뒤치락 | 사인파 두 개로 ±0.25칸 (3.5.1) |
| 바람 / 불꽃 | 다수 전진 시 바람, 부스터 시 불꽃. **바람은 트랙 좌표를 따라 흐른다** (3.5.2) |
| 카드 슬램 + VS | 양쪽에서 쾅 → 충돌 → VS 또잉 (3.6.1) |
| 결과 공개 | **도장 + 화면 흔들림**, 집계 **카운트업**, 순위표 **FLIP 재정렬** |
| 특수 라운드 | 배너가 슬라이드+오버슛으로 등장 |
| 올인 베팅 UI | 10~50% 슬라이더. 봇은 기본 20% |
| 사운드 | **Web Audio로 전부 합성**. 음소거 토글 |

#### 사운드는 파일을 쓰지 않는다

클릭·초읽기·도장·대시·불꽃·좌절·결승 — 전부 오실레이터와 필터드 노이즈로 만든다.
받을 파일이 없으니 404도 없고, 전체가 몇 KB다.
**나쁜 연결에서 사운드 스프라이트를 받느라 첫 라운드가 늦는 폰 게임은 고장 난 것처럼 느껴진다.**

`AudioContext`는 사용자 제스처 전에는 시작할 수 없으므로 첫 `play()`까지 만들지 않고,
거부당하면 조용히 아무것도 안 한다.

#### 밸런스 재검토 결과 — 규칙은 바꾸지 않았다

Phase 2에서 남긴 이슈(순응형 20.1%)를 다시 봤지만 **그대로 두기로 했다.**
특수 라운드 비중을 늘리는 안을 검토했는데, 12라운드 중 3개가 이미 특수 라운드고
더 늘리면 "평범한 판"이 6개밖에 안 남아서 눈치게임의 기본 리듬이 무너진다.

현재 수치는 그대로다 — 최다 우승 21.1%, 선두 교체 2.96회/게임, 최하위 6.6%.
**어떤 성향도 죽지 않았고 선두가 계속 바뀌므로 치명적이지 않다**고 판단했다.
진짜 판단은 사람이 붙는 Phase 4에서 나온다. 봇의 순응은 파라미터지만
사람의 순응은 눈치를 본 결과라서, 같은 20%가 아닐 수 있다.

### Phase 4.5 — 계정과 로그인 (1~2일)

온라인이 붙고 나면 "누구"가 필요해진다. 지금은 `src/net/identity.ts`가
**브라우저에만 저장되는 익명 신원**(닉네임 + 랜덤 id)을 돌려준다.
게임은 id와 표시 이름만 물어보므로, 로그인을 붙이는 건 **이 파일 하나를 바꾸는 일**이다.

| 단계 | 내용 |
|---|---|
| 지금 | `provider: "local"` — localStorage, 계정 없음. 닉네임만 |
| 로그인 도입 | Supabase Auth (카카오 / 구글 / 이메일 매직링크) → `provider: "supabase"` |
| 마이그레이션 | 로컬 신원으로 쌓인 전적을 로그인 시 계정에 귀속 |
| 그 다음 | 전적·통계("너는 다수파 68%")·랭킹이 계정에 붙는다 |

> **중학생이 쓰는 서비스라 비밀번호를 직접 받지 않는 쪽이 낫다.**
> 소셜 로그인이나 매직링크면 비밀번호를 저장할 일도, 잃어버릴 일도 없다.
>
> 그리고 **로그인을 강제하지 않는다.** 익명으로도 끝까지 플레이할 수 있어야 하고,
> 로그인은 전적을 남기고 싶을 때 하는 선택이어야 한다.

`localStorage`는 시크릿 창이나 사이트 데이터 차단 환경에서 **읽기·쓰기 자체가 예외를 던진다.**
`identity.ts`는 전부 try/catch로 감싸서 저장이 안 되면 그냥 매번 새 익명 신원으로 돈다.
