    01 · 라운드 구조

    한 라운드 20초

    딜레마 제시(10초) → 전원 동시 선택 → 집계 공개 → 이동 → 순위 갱신. 총 12라운드, 또는 결승선 40칸 선착.

    제시

    집계

    마감 후에만 비율을 공개한다. 이 순간이 게임의 하이라이트.

    이동

    02 · 밸런싱

    다수만 이기면 재미없다

    "다수 +1, 소수 0"으로만 두면 무리가 통째로 뭉쳐 이동해서 순위가 끝까지 안 갈린다. 1등이 안 바뀌는 레이스는 볼 이유가 없다. 그래서 비율에 따라 보상을 비틀었다.

    상황이동노림수
    기본+2칸무난한 판
    압도 — 다수 85%↑ (7-1, 8-0)+1칸뻔한 선택은 이득이 적다
    극소수 — 소수 30% 미만 (1~2명)부스터다음 라운드 다수면 +6칸
    동점전원 +1칸아무도 못 읽은 판. 레이스는 멈추지 않는다
    🔬 "박빙 +3칸"은 폐기했다 — 1000판 시뮬레이션

    8명에서 나올 수 있는 분할은 5-3(62.5%) / 6-2(75%) / 7-1(87.5%) / 8-0뿐이다. "51~60%" 구간은 애초에 존재할 수 없어서 +3은 한 번도 발동하지 않는 죽은 코드였다. 임계값은 실제로 나올 수 있는 비율 사이에 놓아야 한다.

    임계를 65%로 고쳐 5-3에 +3을 주자 오히려 순응형이 유리해졌다. 5-3의 5쪽은 결국 군중이고 순응형 봇이 거기 앉아 있기 때문이다 — 무난이 우승률 18.7% → 19.5%, 선두 교체 3.10회 → 2.46회. 좁게 이긴 쪽에 더 주는 건 읽은 사람이 아니라 따라간 사람에게 주는 보상이었다. 그래서 일반 승리는 일괄 +2, 눈치를 보상하는 무게는 전부 부스터로 옮겼다.

    부스터가 이 게임의 심장

    "다들 A 고를 것 같은데… 일부러 B로 가서 부스터 먹고 다음 판에 크게 갈까?" 지금 지는 걸 감수하고 다음을 노리는 도박이 생기는 순간, 눈치게임이 두 겹이 된다. 한 겹은 "남들이 뭘 고를까", 다른 한 겹은 "남들이 내가 뭘 고를 거라 생각할까".

    특수 라운드

    라운드이름규칙
    05더블이동 거리 2배
    08역전소수가 전진, 다수 제자리 — 시작 전 미리 공지
    12올인자기 칸 수 일부를 베팅. 다수면 2배, 소수면 잃음

    미리 공지하는 게 핵심이다. 역전 라운드인 걸 다들 아니까 다들 소수를 노리고, 그러면 소수를 노린 쪽이 다수가 된다. 규칙 한 줄로 심리전이 한 바퀴 더 돈다.

    03 · 최우선 과제

    레이스 시각화

    이 게임은 규칙이 단순해서 보는 맛이 전부다. 그래서 게임 로직보다 먼저 만든다. 렌더링은 한 기술로 밀어붙이지 않고, 각자 잘하는 걸 시키는 하이브리드로 간다.

    DOMUI 레이어딜레마 카드 · 타이머 · 순위표 · 집계 바
    Canvas파티클 레이어먼지, 스피드라인, 부스터 불꽃, 결승 컨페티. 수백 개가 도는 건 캔버스가 압도적으로 빠르다
    DOM캐릭터 레이어러너 8명. DOM으로 두면 CSS 애니메이션과 개발자도구 디버깅이 쉽다
    SVG트랙 레이어곡선 path, 칸 눈금, 결승선
    CSS배경 레이어패럴랙스 3겹 (0.2 / 0.5 / 1.2배속) × 테마 4종

    곡선 트랙

    직선은 지루하다. SVG <path>로 구불구불하게 그리고 getPointAtLength(진행도 × 전체길이)로 좌표를 뽑는다. 같은 함수로 접선 각도까지 구해 캐릭터를 트랙 방향으로 기울인다.

    차는 실제로 간다 ✓ 구현

    처음엔 배경만 흘리는 트레드밀로 만들었는데 두 군데서 틀어졌다. 출발 위치에서 차가 제자리 미끄러지는 것처럼 보이고, 도로가 곡선이라 가로로만 미는 배경은 도로 방향과 어긋난다. 그래서 진짜로 전진시킨다 — 도로 위의 모든 것(차·눈금·출발선·결승선)을 점수 + cruise에 그린다. 전부 같은 오프셋이라 서로 간의 거리는 정확히 점수 그대로고, 결승선도 20칸 앞에 그대로 있어서 1위가 20칸에 닿는 순간 실제로 만난다. 카메라가 따라가면 패럴랙스는 저절로 흐른다. 출발선 뒤로도 도로를 깔아야 둥근 끝단이 안 보인다.

    바람과 불꽃 ✓ 구현

    전원이 같은 속도로 붙어 가면 대형이 뻣뻣해서, 주기가 다른 사인파 두 개로 ±0.25칸 안쪽에서 미세하게 엎치락뒤치락하게 했다. 다수 쪽이 전진할 땐 차 뒤에서 흰 바람 줄기가, 부스터가 터질 땐 불꽃이 화르륵 뿜어져 나온다. 단 불꽃이 바람에게 파티클 풀을 뺏긴다 — 7대가 동시에 바람을 뿜으면 풀이 바닥나서 하필 같은 프레임의 부스터가 자리를 못 잡는다. 풀을 키우고 불꽃을 먼저 처리해야 하고, 이펙트는 연출 공개가 아니라 실제 이동 시점에 걸어야 한다 — reveal에 걸었더니 차가 움직이기도 전에 끝나 있었다.

    카메라

    선두와 꼴찌를 모두 담되 선두 쪽에 여유를 준다. SVG viewBox를 매 프레임 lerp(0.08)로 보간하고, 순위가 크게 뒤집힐 땐 살짝 줌아웃했다 돌아온다.

    배경이 진행도다 ✓ 구현

    새벽 학교 → 한낮 운동장 → 도시 밤 → 우주. 라운드가 아니라 선두의 진행도에 물려 있다. 네 테마를 겹쳐 쌓고 인접한 둘의 opacity를 교차시켜서 컷이 아니라 디졸브로 넘어간다. 숫자를 안 봐도 얼마나 왔는지 보인다.

    도로 색도 같이 바뀌어야 한다

    배경만 밝히면 도로가 땅에 묻힌다. 테두리·노면·중앙선 3색을 테마별로 두고 배경과 같은 가중치로 RGB 보간한다. 한낮에는 밝은 회색 아스팔트에 흰 중앙선, 우주에서는 보라 노면에 네온 중앙선. 이래서 배경 테마를 Phase 3이 아니라 Phase 1에서 당겨 넣었다 — 나중에 넣으면 레이서·도로 팔레트를 처음부터 다시 잡아야 한다.

    레이서는 경주용 차

    위에서 내려다본 F1 스타일 — 넓은 뒷바퀴, 뾰족한 코, 리어윙, 콕핏. 차 모양이라 스쿼시를 원보다 훨씬 세게 줄 수 있다. 원을 늘이면 그냥 깨진 원이지만, 차를 제 길이 방향으로 늘이면 모션블러로 읽힌다. 최대 scale(1.62, 0.72).

    성능

    transform / opacity만 애니메이트하고 파티클은 객체 풀링으로 재사용한다. 목표 60fps, 저사양에선 파티클 수 자동 감소.

    딜레마 카드 등장

    A와 B가 양쪽 화면 밖에서 쾅 날아 들어와 가운데서 부딪힌다. 부딪히는 순간 그 자리에서 VS가 또잉 하고 튀어나오고, 카드는 반동으로 좌우로 밀려나 제자리에 앉고 VS는 둘 사이 가운데에 남는다. 총 0.62초 — 위 목업에서 라운드마다 돌아간다. 타이밍은 셋이 공유한다: 카드가 만나는 지점이 38%라서 VS도 거기서 시작해, 카드가 아직 튕겨 나가는 동안 1.75배까지 오버슈트했다가 가라앉는다.

    결과 공개 타임라인

    집계가 열리는 2.6초. 여기에 게임의 감정이 전부 몰려 있다.

    • 0.0s딜레마 카드가 3D flip으로 뒤집힌다
    • 0.3s집계 바가 좌우에서 차오르고 숫자가 카운트업
    • 0.8s"다수!" 도장 쾅 — scale 1.6→1, 화면 흔들림 5px
    • 1.0s다수 캐릭터 동시 대시 — 먼지 파티클 + 스피드라인 + 잔상
    • 1.8s소수 캐릭터 좌절 — 제자리 점프, 땀방울
    • 2.2s순위표 FLIP 애니메이션으로 재정렬
    • 2.6s부스터 획득자 머리 위 불꽃 아이콘

    이동은 cubic-bezier(.22,1,.36,1) 0.8초 — 확 튀어나갔다 부드럽게 멈춘다. 달릴 때 squash & stretch를 넣으면 코드 몇 줄로 체감 퀄리티가 두 배가 된다. 대신 prefers-reduced-motion 대응과 화면흔들림 OFF 옵션은 필수.

    Phase 1에서 실제로 부딪힌 것

    위 목업은 가로 화면이고 앱은 세로 9:16이다. 그대로 옮길 수 없어서 수치를 다시 잡았고, 그 과정에서 나온 것들이 아래 넷이다. 전부 세로 화면 특유의 문제라 미리 알아둘 값어치가 있다.

    레이스 뷰는 밴드다

    세로 박스에 가로 트랙을 넣으면 위아래가 통째로 빈다. 화면을 채우지 말고 13:9 밴드로 고정하는 게 답이었다. 남는 아래 공간이 딱 딜레마 카드와 순위표 자리라, 결국 실제 게임 레이아웃과 같아진다.

    8명 레인이 세로를 다 먹는다

    간격을 좁히면 한 덩어리로 뭉치고 넓히면 하늘이 사라진다. 레인 간격은 13으로 두고 트랙 방향으로 ±3.5씩 지그재그를 줘서 풀었다. 0.125칸이라 순위를 오독할 정도는 아니고, 눈으로는 확실히 갈린다.

    카메라로 전원을 담으려 하지 말 것

    막판엔 스프레드가 트랙 전체라 다 담으면 전부 점이 된다. 줌 상한 1.7배를 두고 넘으면 꼴찌는 화면 밖으로 보낸다 — 그러라고 순위표가 있다. 그리고 줌아웃하면 월드 바닥 아래가 보이므로, 배경 언덕은 WORLD.h + 400까지 채워야 밝은 이음선이 안 생긴다.

    애니메이션은 React 밖에서

    칸 위치만 state로 두고 화면 좌표·스쿼시·카메라는 ref에 직접 DOM으로 쓴다. 8명이 달려도 리렌더가 0이다. 참고로 스쿼시는 생각보다 훨씬 약해야 한다 — 0.45로 넣었더니 캐릭터가 그냥 타원이 됐고, 0.16이 적당했다.

    타이머 이펙트

    10초 카운트다운은 단순한 숫자가 아니라 이 게임의 긴장 그 자체다. 레이스 화면 우측 상단에 원형 링 게이지로 띄운다. 위 목업에서 직접 돌아가고 있다.

    색이 시간을 말한다

    남은 시간에 따라 링 색이 흐른다 — 시안(여유) → 앰버(주의) → 코랄(촉박). 단계별로 툭툭 바뀌는 게 아니라 RGB 보간으로 이어지고, 마지막 3초 구간은 pow(t, 2) 커브를 태워서 빨강이 빨리 온다. 숫자를 안 읽어도 몸이 먼저 안다.

    잠금 핍 — 가장 중요한 부분

    딜레마 카드 바로 위에 인원수만큼 핍이 놓이고, 누군가 선택을 확정할 때마다 왼쪽부터 하나씩 채워진다. 몇 명이 이미 골랐는지는 보이지만, 뭘 골랐는지는 안 보인다. 정보는 한 톨도 안 흘리면서 압박만 정확히 전달한다. 링 둘레에 점으로 돌려봤더니 영락없는 타이어라, 고민하는 자리인 카드 쪽으로 내렸다.

    마지막 3초

    링이 심장박동처럼 scale 1 → 1.11로 뛰고, 화면 가장자리에 붉은 비네트가 같은 박자로 숨 쉰다. 앱에서는 여기에 햅틱 진동을 얹는다.

    끝나는 방식 두 가지

    내가 고르면 링이 골드로 잠긴다. 시간이 다 되면 링이 부풀며 흩어지고 자동 랜덤 선택 — 한 명 때문에 게임이 멈추면 안 되니까.

    구현은 setInterval이 아니라 performance.now() 기준 requestAnimationFrame으로 간다. setInterval은 탭을 옮기거나 프레임이 밀리면 시간이 조금씩 어긋나는데, 온라인에서 그 오차는 내 화면과 남의 화면의 마감 시각이 달라진다는 뜻이라 그냥 버그다. reduced-motion에서는 pulse와 비네트만 끄고 링은 남긴다 — 남은 시간은 연출이 아니라 정보다.

    04 · 콘텐츠

    딜레마 카드

    시각화가 아무리 좋아도 딜레마가 시시하면 게임 전체가 시시하다. 재미의 절반은 여기서 나온다. 

    {
  "id": "school_012",
  "category": "학교생활",
  "a": { "text": "숙제 안 하고 지금 놀기", "emoji": "🎮" },
  "b": { "text": "숙제 먼저 하고 나중에 자유시간", "emoji": "📚" },
  "popularBias": 0.38   // 사람들이 A를 고를 예상 비율
}

    popularBias는 봇 AI와 난이도의 기준값이 된다. 상상으로 채우지 말고 친구 20명한테 실제로 물어보고 채운다. 카테고리는 학교생활 / 인간관계 / 먹을거 / 도덕적 딜레마 / 미래·진로 / 완전 헛소리. MVP 40장(12라운드 × 3판 안 겹침), 정식 150장.

    05 · 봇

    성향을 읽히게 만든다

    봇이 그냥 랜덤이면 눈치게임이 성립하지 않는다. 각 봇에 성향 파라미터를 주고, 이름으로 그 성향을 드러낸다. "쟤는 어차피 반대로 갈 거야"를 읽을 수 있게 되는 순간 게임이 한 겹 깊어진다.

    봇성향행동
    무난이conformity 0.9거의 항상 인기 있는 쪽
    청개구리contrarian 0.8일부러 소수로 간다
    눈치백단conformity 0.8 / noise 0.1흔들림 없이 다수를 읽는다
    도박러risk 0.9부스터와 베팅을 노린다
    대충이noise 0.7그날 기분대로
     
    p = popularBias
p += conformity  × (popularBias - 0.5) × 0.8   // 인기 쪽으로 증폭
p -= contrarian  × (popularBias - 0.5) × 1.4   // 뒤집기
p += (random - 0.5) × noise
choice = random < clamp(p, 0.02, 0.98) ? A : B

    08 · 순서

    만드는 순서

    약 12~14일. 시각화가 앞에 오는 게 이 순서의 전부다.

    PHASE 0 준비 ✓ 완료 Vite + React + TS 세팅, 폴더 구조, 세로 9:16 레이아웃 셸, GitHub Pages 배포 워크플로. .stage가 9:16을 강제하고 데스크톱에서는 레터박스로 감싼다 — 두 벌이 아니라 같은 레이아웃 한 벌이라, Capacitor 래핑이 재작성이 아니라 감싸기로 끝난다. 0.5일
    PHASE 1 레이스 시각화 프로토타입 ✓ 완료 src/race/ — SVG 곡선 트랙, 경주용 차 8대, ease-out 이동, 스쿼시&스트레치, 잔상·먼지·스피드라인 파티클, 테마 4종 패럴랙스 배경, 팩 프레이밍 카메라, 체커 결승선. 게임 로직은 일부러 하나도 없다. 폰·노트북 모두 60fps. 2~3일
    PHASE 2 싱글 게임 루프 ✓ 완료 딜레마 40장, 라운드 상태머신, 봇 AI, 이동 규칙 + 부스터, 특수 라운드 3종, 결과 화면. game/은 렌더링을 전혀 모르기 때문에 화면 없이 시뮬레이션할 수 있다 — npm run simulate로 1000판. 결승선은 40칸에서 20칸으로 줄였다: 40칸에서는 12라운드 동안 1위가 평균 14칸까지밖에 못 가서 체커 깃발이 장식이었고, 배경 테마가 선두 진행도에 물려 있어서 4번째 테마(우주)를 실제 게임에서 아무도 못 보고 있었다. 20칸으로 줄이니 91.4%가 결승선에서 끝난다. 남은 이슈는 순응형 우승률 20.1% — 이상치 12.5%보다 높다. 2일
    PHASE 3 연출 다듬기 진행 중 완료 — 상시 주행(트레드밀 폐기, 실제 전진), 엎치락뒤치락 jostle, 다수 전진 시 바람, 부스터 불꽃, 딜레마 카드 슬램 + VS.
    남음 — 결과 공개 타임라인 전체, 사운드, 특수 라운드 연출, 올인 베팅 UI(현재는 자기 칸의 20% 자동), Phase 2에서 남긴 밸런스 이슈 재검토.     2일
    PHASE 4 온라인 멀티Supabase 스키마 + RLS, 방 생성·참가, 서버 집계, 봇으로 빈자리 채우기, 끊김 처리 3~4일
    PHASE 4.5 계정과 로그인 온라인이 붙으면 "누구"가 필요해진다. 지금 src/net/identity.ts가 브라우저에만 저장되는 익명 신원(닉네임 + 랜덤 id)을 돌려주고, 게임은 id와 표시 이름만 물어본다 — 그래서 로그인을 붙이는 건 이 파일 하나를 바꾸는 일이다. Supabase Auth로 카카오·구글·매직링크. 비밀번호는 직접 받지 않고, 로그인을 강제하지도 않는다 — 익명으로도 끝까지 플레이할 수 있어야 하고 로그인은 전적을 남기고 싶을 때 하는 선택이어야 한다. 1~2일
